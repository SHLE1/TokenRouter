# 模型目录与市场

本文描述模型可请求目录如何从分组、价格配置和提供商能力解析，并如何投影为公开模型市场的品牌、价格、容量和可用性。它不固化供应商的完整动态模型清单，也不定义最终用量结算事务。

- [市场可见性](#市场可见性)：修改公开分组过滤、品牌或排序时读取。
- [目录元数据查询](#目录元数据查询)：修改名称写法、档位别名及能力来源时读取。
- [价格展示](#价格展示)：修改价格配置价格、倍率或未知价格时读取。
- [容量与可用性](#容量与可用性)：修改公开容量或探测时间序列时读取。
- [一致性边界](#一致性边界)：核对目录、市场和真实调度是否一致。
- [模型属性配置](#model_attributes)：修改默认属性、分组覆盖或客户端配置导出时读取。

<a id="model_catalog_resolution"></a>
## 目录解析

公开市场的分组筛选、逐请求提供商预取/排序、辅助容量与可用性、动态设置和输出组合已由 `routing.Marketplace` 执行；`routing/httpapi` 直接提供模型与公开统计 HTTP。app 绑定唯一分组存储、settings.Store、billing 报价及原 Dashboard 统计读取，平台默认目录与显示名由 `routing/provider` 投影，app 直接注入选项，保留动态目录的原读取时点。市场展示、价卡和元数据测试直接验证 routing.Marketplace；网关目录与实际查价的一致性测试也直接组合原生市场端口，不构造另一份市场服务。

`routing.RequestableResolver` 唯一负责可请求候选合并、分组白名单、请求模型 → 分组映射模型 → 上游模型 及价格歧义判断。`routing.RequestableCatalogue` 组合候选读取与模型列表短缓存，由 app 直接绑定 provider 存储。`gateway/provider.ModelPolicy` 为目录和实际转发提供同一套平台模型判断，提供商记录与本次 attempt 的模型链分开传入。提供商模型范围与一跳匹配由 provider 提供，平台专有资格、thinking/模型限流观测和动态默认目录通过窄接口接入。

`routing.ModelList` 由 app 按原 TTL 构造一次，按分组及入口强制平台条件区分目录，保留 nil 结果、失效范围及全进程指标，仍由应用时间轮按原频率清理。请求模型与公开模型都使用同一可请求解析边界：从当前分组的可调度提供商能力生成候选，再执行 Key/分组/提供商的模型映射和范围校验。已有分组的目录来自该组提供商的实际模型与协议能力；解析结果为空时保持为空，不回退到一个假设的平台默认列表。创建分组时的管理候选可以聚合各平台默认目录供编辑参考，这些建议不等同于已可请求模型。

网关四类模型目录 HTTP 由 app 直接构造 `gateway/httpapi.ModelsHandler`，复用同一 `routing.RequestableCatalogue`。平台展示数据由 `gateway/provider.ModelDisplayCatalogue` 提供；`gateway/modeldisplay` 只保存原展示值、稳定合并与默认列表规则。HTTP 负责 Key 别名、自定义列表和各协议的响应形状。Gemini 原生列表与单模型查询只保留支持 `gemini_generate_content` 的可请求模型，并使用本地 Gemini 元数据；空结果不会通过单个上游或静态默认列表补全。单模型查询必须先通过同一目录验证，未知或不在当前权限范围内的模型返回 404。复合 Key 逐绑定检查分组权限与协议，再附加前缀；强制 Antigravity 路径只过滤提供商平台，仍遵守分组协议和模型限制。

提供商映射由 `provider.ResolveModelMapping` 解析，默认范围由 `provider/provider.DefaultProviderModels` 按提供商平台、认证类型和特定资格提供。缺失或空白名单使用默认目录；显式映射可以加入自定义请求名，非空白名单限制最终模型。末尾通配符和 `*` 只参与匹配，不作为模型 ID 返回。透传开关不跳过这层检查。返回映射是独立值；读取时不再修改提供商内的派生缓存，避免调度/展示并发读取以及调用方修改结果污染后续请求。原精确/通配匹配继续复用 `routing/modelmap`；Qoder 专有资格和默认目录由平台规则适配器提供，请求改写仍在原执行时点发生。分组模型拒绝提示由 routing 聚合候选，gateway/provider 提供站点默认目录；只在候选合资格且没有显式模型时读取默认目录，显式配置过滤为空时保持非 nil 空集合。

管理端提供商测试模型目录由 `routing.AdminCatalog` 组合显式平台、提供商认证形态与懒解析的请求模型；默认目录通过 app 注入 `routing/provider.AdminCatalogOptions`，在调用时读取原平台快照。OpenAI 透传仍使用明确的模型范围；Gemini Google One/OAuth、Antigravity、Qoder 站点与 Spark 影子提供商保留各自的能力边界，Grok 动态目录按需读取。HTTP 分别保留 OpenAI、Grok 和 Claude/Gemini 类模型的零值字段、省略字段及空数组/null 形状；没有将管理测试目录等同于提供商可执行能力。

用户可见分组目录提供 `models: string[]` 和 `model_protocols: Record<string, ProtocolID[]>`。后者列出每个模型当前可请求的客户端入口；两者仅用于控制台展示与配置生成，不替代请求时的权限和资格校验。Key 列表内嵌分组未带目录时，前端按分组 ID 复用可见分组列表，不逐行猜默认模型。

Claude Code、Codex、Gemini、Grok、OpenCode 与 CC Switch 配置按用户选择的客户端协议和真实模型生成。存在 `model_protocols` 时按该投影过滤；目录为空时不生成虚构示例。Key 级精确/最长尾通配符映射按一跳目标投影可用模型和协议，复合 Key 示例加回已绑定前缀；导出不因为品牌或模型名称添加 `/antigravity` 等强制平台路径。tf CLI 回环协议保持原格式。

模型 ID 是客户端请求键，display name 是展示信息，pricing model 是定价解析键。三者可以不同。Key 级重定向和分组映射必须让 `/v1/models`、`/models`、实际调度和响应模型恢复保持一致；目标不可请求的别名不应只出现在列表里。

## 市场可见性

公开市场只返回 active、非 exclusive、且至少有一个 active provider 的 Group。每个 Group 在解析后没有可请求模型时也会被隐藏。排序使用 Group 的显式顺序；市场不会按临时价格或实时错误任意重排产品。

展示品牌优先使用 `display_brand`，为空时回退 Group name。公开分组投影包含描述、品牌、倍率和模型数，不返回单一上游平台。模型仍可携带自己的厂商与能力信息，展示品牌不决定执行提供商平台。

模型级投影附带 `attributes`，其中包含有效显示名、长度、模态和能力信息；`input_modalities`/`output_modalities` 保留为兼容字段。新属性投影的未知字段不根据价格或名称猜测，旧接口未返回 `attributes` 时才保留前端历史模态推断。属性读取失败不阻塞价格展示。

## 目录元数据查询

`modelcatalog` 解析 models.dev 统一目录并拥有供应商身份索引、属性与内容版本。`modelcatalog/provider.Service` 在应用生命周期中下载、缓存和原子发布统一目录及其价格投影；`billing/pricing` 将目录报价归一为 `CatalogModelPricing` 计费模型，并解释本地补充、覆盖及计费回退。app 的独立目录装配只创建一个运行实例，计费和属性消费者共享该实例。目录维护步骤封装在运行时内，对外提供生命周期、查询、快照和强制更新。价格与属性不会独立更新，候选目录失败时保留整个旧版本。代理失败策略及 URL 校验继续由现有出站边界执行。

生产只使用 models.dev 加载流程，远程入口为 `https://models.dev/catalog.json`，按 `pricing.check_interval_minutes` 默认每 10 分钟检查，使用 ETag 条件请求和本地内容摘要；管理员可强制更新。程序内嵌经过解析验证的压缩离线快照，并附 models.dev 的 MIT 许可。首次启动和网络故障可以使用磁盘或离线目录，缓存文件为 `models_dev_catalog.json`，完整解析成功后通过临时文件替换。管理员接口返回版本、最近成功更新时间与最近更新错误。 本地文件在合并前将旧 `litellm_provider` 归一为 `provider`，显式新字段（含空值和 `null`）优先；内部来源分类为 `catalog`，不会覆盖实际数据出处。远程 304 不跳过本地层校验。

裸模型名优先选原厂记录。明确的 `canonical_model_id` 归属优先；关联缺失时，已知原厂端点（包括 OpenAI、Anthropic、Google、xAI、Mistral 等）仍可识别为原厂，不要求每个模型同时存在于公共资料表。原厂端点托管的其他作者模型继续按明确的 canonical 归属识别。Azure、OpenRouter 等独立供应商不通过该兜底获得原厂身份；其他来源无法确定时保留歧义，不从遍历顺序中选价。供应商限定名称先精确匹配，已知供应商前缀不会在查询时被删除而借用其他来源。只含模型公共资料的记录也能参与属性查询，无需具备价格。

公开市场通过 `billing.PriceResolver.PublicQuote` 使用与实扣一致的价卡解析。价格和属性按完整模型 ID 查询，仅清理大小写、首尾空白及已知 Google 资源路径；供应商限定名保持来源隔离。Claude 点号与短横线、日期版本和档位后缀都是独立身份，不互换、不补全。完整目录条目独立生效，不从基础条目拼接价格、缓存、上下文阶梯或能力字段。

价格配置价卡先按原始请求名匹配精确/通配规则，再查询同一型号的协议资源路径候选。完整型号的显式价卡和零价均保留，价格查询不按分组或提供商平台隔离。没有完整型号价格时返回未定价，不剥离日期、effort 后缀或供应商名称借价。

Gemini、OpenAI、Claude 和 Grok 的模型后缀按完整 ID 处理，不生成基础型号候选或 effort。上游真实提供的 `high`、`low`、`medium`、`tiered`、`max`、`thinking` 等完整型号仍可配置独立价格和属性。Grok 的运行时默认文本模型只用于允许省略模型的请求，不参与目录别名查询。

GPT-5.6 系列的内置目录、白名单和配置导出只提供 `gpt-5.6-sol/terra/luna`，不注册裸 `gpt-5.6`，也不把裸名称自动重定向到 Sol 或旧 GPT。外部目录或管理员配置的显式条目仍遵守通用查表规则；裸名称缺少显式定价时不借用 Sol 或默认 GPT 价格。

展示属性读取 models.dev 的 `modalities.input/output`，支持文字、图片、音频、视频和 PDF。字段缺失及零长度表示未知或不适用；显式 false 与空模态数组会保留。本地旧价格 JSON 的模态推断只用于兼容价格消费者，分组有效属性使用独立解析器。

目录未命中时，只允许完整型号精确命中已有静态价格；不使用日期、系列、Spark 跨型号重定向或默认型号猜价。静态价格不向能力查询提供继承依据，也不改写公开模型 ID 或上游请求 ID。

models.dev 的目录、属性和本地覆盖在同一版本发布，只读快照使用相同的完整身份规则。原厂裸名与明确供应商记录仍按来源索引查询，本地覆盖、显式零价和本地新增条目保持有效；未知型号不会从目录遍历顺序中选价。

## 价格展示

模型展示价格与实际结算共用计费解析器，按分组逐模型定价、价格配置有效价格、内置模型价格的顺序选择基础价格，再应用 Group 倍率。分组映射已经给出 pricing model 时，展示层不应再次猜测别名链；分组显式单价或区间不能被价格配置覆盖；仅配置服务层级、Max 推理或分时倍率时继承价格配置/内置基础价，并按字段覆盖同名倍率。管理员配置的积分人民币单价和美元汇率都有效时才展示官方价比例/人民币等价；任一缺失或非法则省略。分组展示和模型计价不通过假定的单一平台分类。

`context_intervals` 是实际用户定价合同。价格配置配置有效 token 区间时按共同的 `(min, max]` 边界展示和结算，并优先于模型内置长上下文规则；价格配置关闭 `long_context_pricing_enabled` 也不会压平这类显式区间。没有有效显式区间而模型含长上下文元数据时，开关开启会合成基础档和长上下文档，关闭则展示并结算单一基础价。模型目录的 `input/output_cost_per_token_above_*k_tokens` 在解析层转换为同一组阈值和倍率；显式 `long_context_*` 字段（含 `0`）优先；解析时会清除该条目的 models.dev 默认绝对阶梯，转而使用显式阈值和倍率，因此阈值 `0` 可以关闭默认长上下文加价。使用 `null` 删除覆盖字段后恢复目录默认规则。

可选 `pricing.override_file` 在目录和回退文件之上按字段浅合并，`null` 表示删除字段，覆盖后的目录仍由展示与结算共同读取。合成长上下文档时，普通与 priority/Fast 的缓存创建、缓存读取价格都按输入侧倍率调整；缓存创建的标准、5 分钟和 1 小时价格来源保持相同倍率语义。展示会补齐显式区间前后及中间有基础价的范围；缺价范围不展示为零价，也不会被其它区间价格代替。只有全部正上下文范围有价且普通/Fast 价格一致时才压平为单价。

返回的零价区间仍保留范围标签和切换入口；JSON 中零金额字段省略不表示该区间缺价。区间价格已经应用 Group 倍率。计费模型、价卡、服务层级、最终 effort、用量、时刻和资金倍率相同时，实际提供商平台不形成额外的售价维度。使用上游模型作为计费来源时，先按提供商映射确定计费模型；不同路线无法形成一致报价时标记歧义，不猜测一个统一低价。

关联价格配置启用 `free_openai_fast` 的分组，其模型广场 Fast 用户价格与同一 Standard 基础价/上下文档一致；Fast 展示资格同时检查默认价和有效区间，只有区间单价的自定义模型同样适用。只调整展示副本，结算的 Fast `total_cost` 和提供商统计不因此改成 Standard。分时倍率沿用既有价格配置展示口径，不新增市场价格的实时刷新。

共享价格配置和提供商统计 API 的 `cache_write_1h_price` 是可选字段。`cache_write_price` 代表 5m 档；当 1h 字段存在时，模型广场和结算按用量中的 5m/1h 明细分别计价，并在公开 DTO 中下发两个单价；字段缺失则保持历史单价行为。

未知或歧义价格使用 `unpriced`/unknown 状态，不填 0。显式价格指针为 0 才表示免费。Qoder 内置别名和路由键也使用通用价格回退，有内置价即可使用；具体优先级见[Qoder 原生上游](qoder_upstream.md)。

## 容量与可用性

市场接口可以附加 Group capacity 和历史 availability summary。容量来自当前提供商/并发投影，可用性只为启用 probe 的 Group 查询；用户侧模型广场和 API Key 分组选择器不展示 capacity，管理员分组管理仍正常展示。两者都是辅助信息：读取失败时仍返回模型和价格，不把缺失观测解释为 0 容量或 0% 可用。

可用性窗口和 bucket 粒度来自运行设置，并有日数、分钟数和最大 bucket 数约束，防止公开接口返回过大序列。时间桶使用配置时区；它不参与实时调度和计费。

每个 Group 的 `availability_probe_config` 还控制探测模型、提示词、间隔、单次尝试超时、User-Agent 和最大重试次数。`max_retries` 表示首次失败后允许追加的尝试次数：旧配置缺失该键时默认 3，显式设为 0 时只执行首次探测，允许范围为 0 到 10。每次尝试拥有独立超时；首次或任一次重试成功后，本轮观测即记为成功并停止继续尝试。一次调度周期只保存一个最终结果，中间失败不单独进入可用率样本。

探测轮次、重试与最终结果编排由 `routing` 拥有，租约、原子保存和历史时间桶查询在 `routing/postgres`；`routing/provider` 提供原 cron 日历调度与平台目录投影。app 注入实例标识、时区和执行端口，提供商选择由 `gateway/provider/selection` 提供，探测执行复用 `provider.TestService`，通过 app 构造的 Probe 适配连接。构造不启动，重复 Start/Stop 不再注册新任务；停止会取消维护、领取与请求预算，并在生命周期的后台总预算内等待在途操作。超时返回失败，不能视作 drain 完成；尚未保存的领取继续按原 PostgreSQL 租约到期规则恢复。

每个实例的 runner 不允许分钟级 cron 轮次重叠；单轮只领取不超过实例 worker 数量的到期 Group，使每个已领取分组都能立即执行，并由 PostgreSQL 租约阻止其它实例重复领取。维护、领取和每个分组的探测分别使用独立超时预算，慢维护不能挤占合法重试窗口。管理 Group API 中不合法的 `availability_probe_config` 统一返回 HTTP `400` 和 reason `INVALID_AVAILABILITY_PROBE_CONFIG`。

永久模型可用性诊断由 `routing.ModelAvailability` 执行，通过独立持久候选查询区分模型缺失和暂时容量不足。所有入口按明确的组内关联查询候选，Antigravity 提供商也不扩大成员范围；失败或无法诊断时仍保守交给 503 分支，不把暂时限流误报为 404。

## 一致性边界

- 市场预取可调度提供商后按提供商全局优先级、提供商 ID 恢复稳定候选顺序；ProviderGroup 只表达成员关系，不保存分组内优先级。预取失败才逐分组回退，不能混用两批不同时间点的数据后宣称原子快照。
- 提供商、分组、价格配置、模型映射或价格更新要失效对应解析缓存和市场查询缓存。
- 上下文区间的边界、输入/输出/缓存单价与实扣必须共用同一定价解析结果，实际提供商平台不成为额外的用户价格键；上游计费模型仍按明确的映射来源确定。
- 市场“可见”只说明当前有产品/提供商/模型投影，不保证下一次上游请求一定成功；真实请求仍经过限流、并发、凭据和策略筛选。
- 新平台必须同时提供默认展示信息、可请求解析、定价未知处理和平台专题，不能只把常量加入下拉列表。

<a id="gateway_default_pricing"></a>
## 管理员默认价格查询

「模型管理」包含「价格管理」和「属性管理」。价格管理保留原 URL，包含「价格配置」和「网关默认价格」两个页签。默认价格通过 `/api/v1/admin/pricing/defaults` 查询，支持模型名、平台、计费模式及分页；`/model` 和 `/models` 分别按模型提供自动填价和统一模型名查询，不要求上游平台参数。默认目录列表中的平台标签用于识别模型来源，不是自定义价卡的查价维度。所有接口继承管理员认证。

工具栏的搜索框与图标筛选按钮放在左侧，平台和计费模式收纳在筛选面板中；右侧的图标刷新只重新查询列表。蓝色「更新目录」按钮通过 `POST /api/v1/admin/pricing/defaults/update` 调用同一个价格服务的强制更新能力：配置了远程来源时重新下载目录并叠加本地覆盖，未配置远程来源时重载本地目录及覆盖层。更新成功后保留当前筛选并重新查询，更新失败显示错误并保留现有列表。更新按钮在请求期间禁用，避免重复提交。

离线手动更新与后台本地重载共用同一流程。缓存文件不可读时优先使用已加载的内存目录，因此缓存目录只读不会阻止本地补充或覆盖文件生效；候选价格仍须完整校验，失败时保留已发布版本及错误状态。该流程自行持有更新锁，调用方不能重复加锁。

列表从当前加载目录取得独立快照，使用同一个 Calculator 的平台规则与静态回退计算基础价格；本地 override 已包含在目录内。查询不触发网络同步，不叠加分组、用户或订阅倍率。价格详情标明 token、图片、视频和倍率单位，并携带缓存、服务层级与长上下文规则。显式零价与未定价分别表达。批量图片和创作台保存的资金、单价快照不会因查询或目录更新而重新计算。

输出模态不决定计费模式。默认价格页只在目录存在明确的按张价格或命中模型专用媒体规则时展示按张、按秒价格，不把历史执行路径的通用媒体兜底当作该模型的报价。聊天模型附带的图片元数据不切换 token 模式。只有 token 报价时按 token 展示，全部缺价时保留未定价；Gemini Image 系列的图片 token 费率解释独立于计费模式，Omni 和 Deep Research 保留普通输出价。按张报价保留显式零值及实际来源，本地覆盖不会标成本地补充。


<a id="model_attributes"></a>
## 模型属性配置

属性配置保存于 `model_attribute_configs`，有名称、描述、启用状态和有序规则；分组关联表以 `group_id` 唯一约束保证每组最多关联一份配置，一份配置可供多个分组使用。规则和关联在同一事务保存，名称或分组冲突整体回滚。属性配置与价格配置独立，停用、删除或解除关联后恢复默认属性。

规则针对可请求解析结果保留的最终上游模型匹配，不读取计费模型。先按明确的模型身份候选查找精确规则，再按配置顺序匹配末尾通配符，只使用第一条命中规则。覆盖按字段进行：缺失键继承，布尔 false 和模态空数组具有显式含义，模态数组整体替换，管理员填写的长度必须是正整数。未知字段不变成不支持或零容量。

模型广场和控制台可见分组在展示时按分组读取一次配置，不保存跨请求的属性配置缓存。写入后沿用分组认证失效通知；其他实例的下一次展示查询直接读取已提交的数据库值。属性不会写入认证或调度快照。分组 DTO 的 `model_attributes` 按公开模型 ID 索引；市场模型的 `attributes` 与兼容模态字段来自同一解析结果。多条路线展示共同能力及已知最小上限，`route_differences` 标明路线差异。API Key 别名导出复用一跳目标的属性，不改变公开名称或协议资格。

管理员接口位于 `/api/v1/admin/model-attributes`：`/configs` 提供分页列表与创建，`/configs/:id` 提供查询、完整更新与删除；`/defaults` 支持搜索、厂商、能力及分页，`/defaults/model` 查询模型属性，`/defaults/models` 返回候选名称。`POST /defaults/update` 与价格页调用同一个更新器。默认页不叠加分组配置，未定价模型的属性也可查询。

属性只用于展示和配置导出，不参与 HTTP、WebSocket、实时会话或媒体任务的准入、参数处理、提供商筛选和故障转移。较小的输出上限或显式不支持某项能力不会新增网关拒绝、删除参数、截断或注入请求参数。现有分组策略、提供商能力和协议兼容行为继续独立执行。

OpenCode 导出显示名、附件、推理、温度、工具调用、模态与长度。其 schema 要求 `limit.context` 和 `limit.output` 同时存在，因此缺少任一项时省略整个 `limit`；不支持的 `structured_output` 和路线差异字段不会写入。Grok 导出可使用有效显示名，其余客户端保留各自现有配置格式，不添加未知键。

### models.dev 计费投影

目录报价以美元/百万 token 提供，内部转换为美元/token。`cost.tiers` 的明确上下文阈值优先于兼容的 `context_over_200k`，多个阶梯保留各自的绝对输入、输出和缓存价，并按 `(min,max]` 口径展示与结算。显式价格配置区间继续优先；关闭内置长上下文规则时不应用目录阶梯。Fast 报价保留明确的零价，展示与结算使用同一投影。

xAI 达到上下文阈值即切换价格。转换层将这类目录阶梯的内部边界减一，例如原始阈值 200,000 对应基础档最大 199,999；结算、模型广场和管理员默认价格页共用转换后的区间。原始目录阈值保持不变，其他供应商继续严格超过阈值才切档。

价格配置的图片输入、图片输出单价覆盖每个目录阶梯，显式零值和未填写的语义在各档保持一致；覆盖与缩放只修改请求使用的价格副本。图片输入未填写或为零时按所在档的文本输入价计费，图片输出未填写或为零时不收取图片 token 费用。

默认目录的图片输出价也保留是否显式存在：目录、本地补充或本地覆盖提供零价时按免费结算，只有该价格桶缺失时才回退文本输出价。

原厂 Google 的 Gemini 生图记录中，`cost.output` 表示图片输出 token 费率，投影到 `output_cost_per_image_token`；文本及思考输出价由媒体补充文件填入，来源标为 `local_supplement`。目录已有的图片费率继续优先于补充文件，管理员本地覆盖仍可分别修改两项价格。该解释只用于原厂 Gemini 生图记录，不套用到 Deep Research 或中继报价。models.dev 缺少完整文本输入、输出价时保持 token 未定价，独立媒体价格仍可查询；显式零价不视为缺失。价格依据见 [Google 官方定价](https://ai.google.dev/gemini-api/docs/pricing)。

原厂 Claude 缺少 1h 缓存单价时按输入价 ×2 派生；供应商限定的中继报价不套用原厂倍率。`source` 与 `price_sources` 区分 models.dev、本地补充、本地覆盖和规则补充。默认本地补充文件只保留媒体专用价格，既有媒体兜底和自定义价格配置继续生效；历史账单及已保存的任务资金快照不重算。媒体补充按“提供方＋原始模型 ID”同步到同一原厂记录的裸名和限定名，先应用补充文件里的精确键，再填补其他等价名称的空缺；日期版本与中继记录不共享补充，显式零值及随后应用的本地覆盖保留各自优先级。

统一目录发布会检查价格解析的逐条诊断。模型价格字段类型错误或嵌套阶梯解码失败时，本轮更新返回包含模型名和字段信息的错误，保留原有价格、属性、版本、更新时间及磁盘缓存，只更新错误状态。仅有属性而没有报价的模型仍是合法目录记录，不因缺价而拒绝属性查询。

目录发布保留逐条解析诊断：未知模型上的无价格补丁会告警并忽略；非法字段或非对象条目拒绝本轮更新。孤立缓存阶梯及单侧阶梯输出诊断，已发布模型的倍率阶梯或绝对阶梯在更新后消失时输出告警，便于确认是否为有意调整。
